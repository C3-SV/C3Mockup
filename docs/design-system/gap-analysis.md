**Riesgos:**
- packages/ui Button/Badge/Card are consumed by apps/admin (out of scope); restyling them would change the admin UI. Keep the DS work inside apps/web.
- Mixing Tailwind v4 preflight with the DS reset: DS globals.css has its own base rules (box-sizing, h1-h3 margin 0, :focus-visible). Order of imports and @layer matters; unlayered DS CSS beats Tailwind utilities, so Tailwind layout classes may be overridden or may override .c3-* unexpectedly. Put DS CSS in a consistent layer or import order and test.
- Dark-to-light flip: every page currently relies on a navy page background (PageShell backgroundClassName bg-[#0F203E]) and white text. Changing the shell/body to white will make unmigrated sections unreadable until their slices land. Land the shell together with, or after, the page slices, or keep a temporary .c3-sitio--dark escape hatch.
- Dropdown nav has no Explorar/Empresas/accounts equivalents; adapting the DS header to a site without accounts needs an owner decision on the primary CTA (proposed: Contacto) and whether Qué es C3/Eventos/FAQ stay as top-level links (7 links may overflow the 900px layout).
- Logo asset: the white logo in the header will be invisible on a white header; the DS blue logo files must be copied into apps/web/public/brand. The DS says to keep the official logos if they exist and the brand manual is not in the package, so confirm with the owner that logo-c3-claro-con-color.png vs c3-sim-azul.png is acceptable.
- Fonts: next/font self-hosting vs the DS Google stylesheet; do not add both (double download). lang es-SV vs es may affect hreflang/locale metadata and the existing SEO tests.
- Violet focus (#6548c7) on a navy footer or dark panels gives low contrast (use #b9a8f0 there); DS dark action (4.13:1) fails, so do not enable dark mode.
- Open questions for the owner: confirm lang es-SV vs es; confirm the header CTA (Contacto) and the footer column structure without Explorar/Empresas/Tu cuenta pages; confirm whether to keep a scroll-progress bar (not in the DS); confirm which logo file for the header; whether Button should keep the 'ghost'/'text' variants for in-text links.
- Existing SEO JSON-LD (getSiteNavigationJsonLd) is derived from navigation content; changing the nav labels (Ecosistema to Conoce C3) changes structured data and any tests pinned to it.

**Pruebas sugeridas:**
- Unit (Vitest/RTL) Navbar: renders a <nav aria-label="Principal">; "Conoce C3" button has aria-expanded=false and aria-controls; click opens the panel with Compite/Crea/Conecta; Escape and mousedown outside close it; the link whose href matches the pathname gets aria-current="page" (mock usePathname); the "Menú" button toggles the mobile panel and navigating closes it.

- Unit PageShell: first focusable element in the document is the skip link, <main id="contenido"> exists exactly once per page (also for app/page.tsx and not-found).
- Playwright e2e at 390px and 1280px: no horizontal scroll (scrollWidth <= innerWidth) on /, /compite, /crea, /conecta, /eventos, /contacto, /faq, /que-es-c3 and a 404; header sticky at 72px (64px on mobile); Menú visible below 900px and the desktop nav visible above it.

- Playwright reduced-motion: emulate prefers-reduced-motion and assert no running animations/transitions on header and buttons.
- a11y (axe-core via @axe-core/playwright) on each public page: color-contrast of nav links, footer links on navy (#b8c4d9 on #0f203e), primary button (white on #6548c7), the skip link; landmarks (banner, navigation, main, contentinfo); touch target size >= 44px for header/footer interactive elements (the target-size rule).
